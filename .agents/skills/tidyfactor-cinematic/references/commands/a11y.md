# Command: `a11y` — Accessibility Pass

## Purpose
`prefers-reduced-motion` is already a hard constraint on every build; this
command covers everything else a scroll-hijacked, canvas-driven page tends
to break — canvas text alternatives, contrast, focus states, keyboard
scroll — as a checkable pass rather than an assumption that "it looks fine
visually" means it's accessible.

## When to run it
- Always, as part of `deploy` (Phase 3), alongside `perf` — same "never
  skip silently" rule.
- User phrasing: "check accessibility", "is this screen-reader friendly",
  "a11y pass", `a11y`.
- Any time `theme` changes the light/dark palette — contrast needs
  re-verification, not just a one-time check at project start.

## What it does
Run every item in `memory/14-accessibility.md`'s checklist against the
current build:
1. Confirm the canvas film container has a one-sentence `aria-label` and the
   `<canvas>` itself is `aria-hidden="true"`.
2. Confirm scroll-triggered sections use opacity-only pre-trigger states,
   never `display:none`/`visibility:hidden`.
3. Check contrast ratios for body and display text against **both**
   `brand.json` palettes (light and dark), not just whichever was open in
   preview.
4. Confirm every non-decorative image (hero cutout, logo, static product
   shots) has real `alt` text.
5. Do a keyboard-only pass: `Page Down`/arrow keys reach the page bottom
   despite Lenis smooth-scroll.
6. Confirm visible focus rings exist on every interactive element,
   especially CTAs where custom styling often removes the default outline.
7. Confirm the hide-on-scroll header never traps focus on a hidden nav link.

## Output convention
```
Accessibility report
  Canvas aria-label:      present   ✅
  Pre-trigger visibility: opacity-only ✅
  Contrast (light):       5.1:1 body / 3.4:1 display  ✅
  Contrast (dark):        4.6:1 body / 3.1:1 display  ✅
  Alt text:                all images ✅
  Keyboard scroll:        reaches bottom ✅
  Focus rings:            visible on all CTAs ✅
  Header focus trap:      none found ✅
```

## Checklist
Same as `memory/14-accessibility.md` — report each item explicitly, don't
summarize as a single pass/fail line.
